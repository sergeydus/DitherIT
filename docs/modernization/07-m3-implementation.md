# M3 — Responsive workspace and visual foundations

M3 implements UX-01, UI-01, UI-02 and the responsive/visual portion of A11Y-02. It retains the M1 controller and processing/export contracts. M4 still owns sample, presets, comparison and pixel-inspection controls.

## Built behavior

- [Workspace](../../src/components/ImageDithering.tsx): source actions, preview/status, inspector/output/export, then a native expandable guide, in the same DOM order on every viewport. At 1024 px and above, the preview uses the flexible left column and the inspector is 320 px with a 24 px gap. Smaller screens use one column. The page scrolls naturally; there is no fixed export bar or sticky inspector.
- One source summary names the image and source dimensions beside Replace image. A labeled Choose/Replace button opens the hidden, still-associated file input, preserving same-file reimport without displaying the native empty-file text. A single output block gives PNG dimensions, alpha behavior and filename beside Export. Ready status is brief; a rendered-settings line appears only while the retained preview is stale. The single debounced polite announcement retains the full result description for assistive technology.
- [Semantic tokens and layout](../../src/app/globals.css) apply specification 02's dark/light colors, Geist Sans/Mono, tabular numbers, 4/8/12/16/24/32 spacing, 8/12 px radii, minimum 44 px controls/label hit areas and 2 px focus outlines with 3 px offsets. Type uses rem units so text enlargement reflows. The transparency checkerboard follows the theme. State/theme foreground and background changes are immediate to avoid intermediate low contrast; border/focus transitions last 150 ms and are removed for reduced motion. Forced colors retain native controls, explicit borders and system focus colors.
- [Theme selector](../../src/components/ThemeSelect.tsx): System/Light/Dark; only `ditherit-theme` is persisted. A static [head bootstrap](../../src/lib/theme.ts) applies the saved theme before body paint. System follows OS changes, including reconciliation at hydration. Storage read/write failures are harmless; a blocked write still applies the session selection. Invalid saved values fall back to System. No image/settings data is stored, and theme changes do not render or alter export bytes.
- [Page metadata](../../src/app/layout.tsx) uses the product title/description and [local SVG mark](../../public/ditherit-mark.svg), also shown in the header. The starter favicon is replaced and the five unreferenced starter SVGs are removed after a repository-reference search. Assets and fonts load under `/DitherIT/` in the production smoke tests.

- [M3 browser coverage](../../tests/browser/m3.browser.ts): 40 screenshots covering empty, ready, processing and import-error states at 320, 390, 768, 1024 and 1440 px in both themes. Every matrix state also runs full-page WCAG-tagged axe checks without exclusions. Separate checks cover theme persistence/OS changes/blocked storage, pre-hydration application with application JS blocked, unchanged PNG bytes, metadata/loaded fonts/mark, 320 px reflow with 200% text plus spacing overrides, forced colors, reduced motion, focus and control targets.

## Interpretation choices and limits

1. The desktop inspector remains in normal flow because its complete control set exceeds many viewport heights. Mobile uses the specified source → preview → settings → output/export → guide order; M4's future view controls will fit between preview and settings. Preview height starts within the specified 240–560 px range and expands naturally for enlarged text.
2. Visible Ready status omits the repeated filename/settings/dimensions; those remain available in the source/output blocks and full polite announcement. Independent export progress shares the one visible status line with render progress. Hidden associated export guidance continues to explain unavailable states without adding another visible summary.
3. Help links to the native guide disclosure rather than opening a popover. There is no modal focus trap or focus-restoration lifecycle. Long source names truncate visually but retain full DOM text and a title; export filenames wrap.
4. The 320 px viewport is the reflow equivalent of a 1280 px page at 400% browser zoom. Text enlargement is tested separately by setting the root font to 200% alongside WCAG text-spacing overrides. These are automated layout checks, not a claim of testing browser chrome zoom or OS assistive technologies.
5. Current automated verification uses Chromium, including simulated OS theme/forced-colors/reduced-motion preferences. Native Windows high-contrast, NVDA/VoiceOver and real-device/browser studies remain recommended and unperformed. M4's A11Y-02 exploration requirements remain pending; no WCAG-conformance claim is made.

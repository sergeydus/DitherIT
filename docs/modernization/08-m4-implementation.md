# M4 — Sample, presets and image exploration

M4 implements UX-02, UX-04, UX-05 and the exploration portion of A11Y-02. It uses the M1 controller's committed Original/Result pair, preserving render/export ownership and raw PNG fidelity.

## Built behavior

- The empty preview offers Choose image and Try a sample. [The bundled sample](../../public/samples/ditherit-study.png) contains grayscale/color gradients, shaded geometry, fine diagonal edges, grain and color swatches. [Provenance and CC0 dedication](../../public/samples/README.md) accompany a [reproducible generator](../../scripts/generate-sample.mjs). Fetching creates a File and calls the same validation/preparation/render path as an upload. Failure is recoverable; cancel, replacement and teardown abort a pending fetch. Native import/theme controls stay disabled until React attaches their event handlers, preventing early input from being lost on slow script loading. The source is identified as `ditherit-sample.png`. Empty source/output copy is plain and descriptive.
- [Presets](../../src/lib/exploration.ts) apply method, depth and soften in one `setSettings` call, retaining seed and output dimensions. The native select has Balanced, Classic texture, Ordered texture and Soft grain; manual effect changes show Custom. Reset selects Balanced and Standard output, retains source/view position, and now **preserves the seed**. This supersedes M2's complete-default seed reset: only New variation changes the selected seed during the session.
- New variation appears only for Random, advances the uint32 seed by one (wrapping at the limit), and announces the new result when ready. Mulberry32 remains the algorithm from M0. At 8 bits, selecting a new seed is explicit but has no pixel effect because noise is bypassed; the UI says so. Imports, presets, output changes, other effect controls and reset retain the seed.
- [ImagePreview](../../src/components/ImagePreview.tsx) owns presentation state. Original/Result/Split are native radios; Split has a 0–100% range, left Original/right Result and a visible divider. It clips draws of the cached baseline/result bitmaps, including transparent edges; it neither builds a fresh Original bitmap nor sends a render job. Downloads always use the controller's committed Result, independently of the viewing option.
- Fit centers without upscaling small images. Numeric zoom is 25/50/100/200/400%, with Fit/100%/zoom buttons, nearest-neighbor display at 100% or above, and a named scrollable viewport. Zoom preserves the viewport center; Fit recenters. Native scrolling and labeled pan buttons work by keyboard, with controls disabled at bounds. Image overflow stays in the viewport, never the page; scroll containment applies only when the image overflows, so Fit still allows normal page scrolling.
- 1:1 detail draws a clamped crop of the current committed view into a 160 × 160 CSS px canvas at one output pixel per CSS pixel. Smaller images are centered, with transparent padding and no upscaling. Padding uses whole-pixel offsets even for odd dimensions, avoiding half-pixel alpha blending. Numeric focus-pixel coordinates, 16 px arrow steps and pointer/tap placement are equivalent paths. A crop outline appears in Fit. Split detail uses the full image's divider coordinate, not the crop center. Stale main/detail previews are explicitly labeled. No viewing/inspection operation changes settings, preparation or output dimensions.

## Interpretation choices

1. View controls are local React presentation state. New validated sources start in Result/Fit, split 50%, detail off; effect/preset/reset changes preserve viewing state. A same-source output resize retains zoom and normalized viewport center, and clamps detail coordinates to the new dimensions. Previous Original/Result remain together until the new render commits.
2. Detail coordinates select a focus pixel (0-based). The crop stays within the image, so an edge focus pixel cannot always be centered. Pointer/tap placement is an enhancement; native numeric controls and arrow buttons provide the complete workflow. Optional divider dragging is omitted because the labeled range is sufficient.
3. Reset retains the current seed to honor the explicit “nothing else re-randomizes” requirement. Presets never change it, even Soft grain. New variation advances deterministically rather than reading system randomness, allowing a session's variation sequence to be reproduced.
4. Display/detail canvases use the committed display bitmaps and have the browser's ordinary alpha-display precision. PNG encoding remains directly from the authoritative committed RGBA buffer; comparison, zoom and crop overlays never enter the exported pixels.
